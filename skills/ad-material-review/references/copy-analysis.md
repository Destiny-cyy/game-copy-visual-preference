# 文案卖点 × 图片素材 × 用户偏好 交叉分析（copy-analysis）

> 本文件讲的是**「哪类文案卖点 / 哪类图片，对哪类用户更有效」**这套进阶分析的方法。
> 它建立在视觉标签体系（`tag-taxonomy.md`）与用户分层（`user-analysis.md`）之上，把「文案」也纳入打标 + 归因。
> **本文件不含任何真实游戏名、平台名、真实业务数据；所有取值一律从 `config.taxonomy` / `config.copy` 读。**

---

## 一、这套方法回答什么问题

素材复盘的传统口径只给图片打标（画风 / 元素 / 福利），只能回答「哪种图更有效」。
但一条投放创意其实是 **文案 + 图片 + 投给谁** 三件事的组合。进阶分析要回答：

- 文案主打什么**卖点**（版本节点 / 福利奖品 / 职业玩法 / 价格…），对哪类用户更有效？
- 文案用了什么**行动钩子**（抽实物 / 限时紧迫 / 价格锚点…）、什么**语气**，效果如何？
- 同一个卖点，配上哪种**福利呈现 / 画风**更强？
- 三类（或 N 类）用户的偏好**一样吗**？哪些卖点是「通吃」的，哪些只对某一类有效？

一句话：把「文案」也翻译成结构化标签，和图片标签、人群标签、CTR 拼在一张表里算。

## 二、两套标签体系，别混（关键）

| | 视觉标签体系 | 文案标签体系 |
|---|---|---|
| 判读对象 | **图片画面** | **文案文本** |
| 判定方式 | 多模态**逐张看图** | 读文案主句 / 全句**人工判读** |
| 维度 | 画风 / 画面元素 / 福利呈现 | 主卖点 / 行动钩子 / 语气句式 |
| 依据文件 | `tag-taxonomy.md` | 本文件 |
| 配置字段 | `taxonomy.style/elements/benefit` | `taxonomy.copy_main/copy_hook/copy_tone` |

⚠️ **绝不用文案里的词去推断画风**（标题写「暗黑」不代表画面是暗黑），也**绝不用画面去推断卖点**。两套各自独立打标，再在归因阶段交叉。

## 三、文案标签体系（结构固定，取值可换）

三个维度，**取值全部来自 `config.taxonomy`**，换游戏 / 换品类只改配置，不动脚本：

| 维度 | 类型 | 判读范围 | 配置字段 | 说明 |
|---|---|---|---|---|
| 主卖点 | **单选** | 只判**主句** | `taxonomy.copy_main` | 这条文案主打的**唯一**利益点 |
| 行动钩子 | **多选** | 判**全句** | `taxonomy.copy_hook` | 催用户行动的手段（抽奖 / 限时 / 价格…） |
| 语气句式 | **多选** | 判**全句** | `taxonomy.copy_tone` | 表达方式（悬念 / 玩梗 / 官方 / 情怀…） |
| 文案置信度 | 单选 | — | `taxonomy.copy_confidence` | 判读自评，把握不足标「中」进复核清单 |

### 三条判定原则

1. **主卖点判主句**：一条文案常有多句（主标题 + 副标题 + 福利清单），只取**第一行非空句**判主卖点；
   冲突时按 `config.taxonomy.copy_main` 里配置的优先级链取第一个命中的（越靠前优先级越高）。
2. **钩子 / 语气判全句且可多命中**：一条文案可同时命中多个钩子、多个语气，各自聚合统计（组间会重叠）。
3. **先定体系再逐条打标**：先按 `copy_main/copy_hook/copy_tone` 的取值列一张「编号 | 主句」清单，
   逐条人工判读成一个 JSON（形如 `{"编号": {"main": "...", "hooks": [...], "tones": [...], "conf": "高"}}`），
   再按主句回填到明细。样例见 `examples/copy_labels.sample.json`。

> 体系怎么建、怎么判定、怎么扩展，遵循 `tag-taxonomy.md` 的四问标准（互斥 / 可判 / 可执行 / 样本够），
> 只是判读对象从画面换成文本。

## 四、数据准备：三个具体坑（都踩过）

进阶分析的源表常是**「一条素材拆成多行、投给不同人群」的规划表**，不是一行一条完整记录。处理规则写在 `config.copy`：

### 坑 1 · 人群写法五花八门，必须归一
源表「定向用户类型 / 广告类型」列常有几十种写法（「老用户-回流」「新进-信息流」…）。
用 `config.copy.segment_map` 把每种原始写法映射到少数几类**核心人群** `config.copy.core_segments`。
- 归一规则是**有序优先级**：命中第一条即停，避免「又像新又像老」被重复归类。
- 映射不到、或为空 → 归为「未标注」，**不进入主分析**（但保留在总体口径里）。
- 核心人群数量不固定，N 类都支持；报告每类一列。

### 坑 2 · 一条素材拆多行，文案/图只在块首行出现
后续行往往只写「投给谁 + 曝光/点击」，文案和图是空的。用 `config.copy.inherit` 声明继承规则：
- **本行有文案/图** → 记为「本行」，并更新「最近素材」；
- **本行没有、但人群已标注** → **继承**最近一条素材的文案与图；
- **本行没有、人群也未标注** → **不继承**（这类通常是排期/汇总行，继承会污染统计）；
- 分时段文案里夹的指引行（「X点-X点文案：」）按 `config.copy.strip_markers` 剔除，不当正文。

⚠️ 继承行常常**日期为空**，所以「按月趋势」在这类表上不可靠，别硬算；口径里要说明。

### 坑 3 · 新表没有图片标签，别重新看图 —— 用「文案桥」复用旧成果
若已有上一轮复盘的**打标台账**（`master.csv` 记录级 + `tagged.csv` 标签），且两张表都写了同一段**完整文案**，
就可以用「文案」当认亲凭据，把新表记录挂到旧台账、复用已打好的画风/元素/福利标签，省掉重复看图打标：
- 用 `config.copy.bridge` 开启并声明三份文件的路径与匹配列；
- 匹配前把文案**归一**：去掉字面 `\n`、零宽字符、全部空白（新旧表的换行/空格格式常常不一致，不归一会对不上）；
- 同一段文案命中多个素材 ID 时，取出现次数最多的，置信度标「中」进复核；
- **挂接率**（借到标签的记录 ÷ 需要借的记录）必须在报告口径里声明；没挂上的记录**不参与图片维度结论**，但**不影响文案维度结论**（两套独立的线）。

> 若没有旧台账，或产品是新文案为主，就走常规流程：逐张看图打标（阶段 3），不用桥。桥是「省重复劳动」，不是必需环节。

## 五、归因口径（五条铁律，违反会得出错误结论）

1. **CTR 一律曝光加权**：`SUM(点击) / SUM(曝光)`，绝不对每行 CTR 取简单平均。每个结论带 **样本量 n / 曝光 / CTR** 三个数。
2. **⭐ 只做同类人群内部比较，绝不跨人群硬比绝对 CTR**：
   老用户 CTR 天然远高于新用户，那是**人群精准度**差异（本来就想玩的人 vs 泛流量），不是素材更好。
   所有「偏好」结论只能是：
   - **同类用户内部**「卖点 A vs 卖点 B 谁高」；或
   - **相对该人群基线**（这类用户整体 CTR）的**提升 pp**（百分点），用虚线在图上标出。
   禁止写「老用户 3.70% > 新用户 0.61%，所以老用户素材更好」这种跨人群结论。
3. **样本不足标注**：`n < thresholds.min_sample` 的组只给**方向性结论**，标注「样本不足」，不当定论。
4. **同素材跨人群**：同一张图投给 ≥2 类人群时，各自算「相对自己基线的 pp」，用来甄别「通吃素材」（各类都跑赢）与「偏科素材」。
5. **混杂检查**：某个卖点特别强时，要检查它是不是被别的东西带起来的（例如「版本节点」组刚好都配了某类福利图）。
   做法：在那个卖点组内部，按第二个维度（如福利呈现）拆开看，若各子组都仍高，说明是卖点本身的效应，不是图片混杂。

## 六、直观分析图（三联条形图）

报告里每个维度画一张图，**每类核心人群一列**，样式（对应 `scripts/build_report_copy.py`）：
- 每列显示该类用户 **TOP-N** 个标签的加权 CTR 横条（N 取 `config.copy.chart_topn`）；
- 条形右侧标注 `CTR (n=…)`；
- 一条**红色虚线** = 该类用户的**整体基线**（`markLine`），超过虚线 = 跑赢自己人群的平均水平；
- 每类人群一个配色，取自 `config.copy.segment_colors`。

维度至少覆盖：`copy_main`（主卖点）/ `copy_hook`（行动钩子）/ `benefit`（福利呈现）/ `style`（画风），
由 `config.copy.chart_dims` 配置，可增删。

> ⚠️ **报告 HTML 必须离线自包含**：画图库（`assets/echarts.min.js`）**内嵌进 HTML**，禁止任何 CDN / 外链。
> 这样双击打开、转发给别人、断网都能出图。交付前用 `scripts/verify_html_charts.js` 跑**运行级渲染验证**
> （真实执行画图代码、确认每张图都画出 SVG），不能只查占位符/语法。边界见 `table-ops.md`。

## 七、结论怎么写

```
【人群 × 主卖点】<分层C_老用户> × <卖点A_版本节点>：CTR X.XX%（样本 N，曝光 XXw）
  是该分层里最高的主卖点，相对该人群基线 +X.XXpp（基线 X.XX%）
  混杂检查：该卖点组内各福利呈现子组均高于基线 → 排除图片效应
  结论：下轮 <分层C_老用户> 文案主句优先讲 <版本事件>，奖品撤到副句
```

优先级给到「**哪个卖点 + 给哪类人群 + 配什么图 + 参考哪条素材**」，而不是笼统说「要多做福利」。

## 八、常见误判（都踩过）

| 误判 | 为什么错 | 正确做法 |
|---|---|---|
| 「老用户 CTR 高 → 主投老用户」 | 人群精准度差异 + 可投放量有限 | 只做同类内部比较，CTR 与曝光规模一起看 |
| 「抽实物钩子 CTR 最高 → 主推」 | 可能只是该组样本个位数 | 标注样本不足，只给方向 |
| 「版本节点卖点最强 → 猛做版本文案」 | 可能混杂了福利图效应 | 做组内混杂检查 |
| 把继承行的空日期算进月度趋势 | 继承行日期多为空 | 说明该类表月度趋势不可靠，别硬算 |
| 挂接率当数据质量 | 它衡量的是「复用旧成果覆盖率」 | 未挂接记录不进图片维度，单独声明 |
| 用文案词推断画风 | 两套体系判读对象不同 | 看图打图片标签，读文打文案标签 |
| HTML 引用 CDN 画图库 | 断网/转发就白屏 | 内嵌库 + 运行级渲染验证 |

## 九、和主流程怎么接

七阶段工作流里，这套进阶分析挂在**阶段 5（效果分析）**：

```
阶段1 取数 → 阶段2 标签体系(本文件第三节补文案体系) → 阶段3 逐张看图打标(或坑3走文案桥)
   → 阶段5  scripts/analyze_copy.py   （归一/继承/挂接/回填/交叉 → copy_results.json）
   → 阶段6  scripts/build_report_copy.py （三联图 HTML，内嵌库、离线自包含）
   →        scripts/verify_html_charts.js （运行级验证）
   → 阶段7  结论落到「下轮做什么 + 给哪类人群 + 配什么图」，进缺口测算与排期
```

脚本全部走 `config_loader`（`config.json` 是唯一事实源），只用 Python 标准库。三分钟空跑见 `examples/README.md`。
