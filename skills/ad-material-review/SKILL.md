# 通用投放素材复盘与效果归因（ad-material-review）

## 目的

把「素材长什么样」和「文案讲了什么卖点」都变成可量化、可对比、可指导生产的结构化字段，据此回答本包的主线问题——**哪类文案卖点 / 哪类图片，对哪类用户更有效**，并产出复盘结论、行动建议与可复用的素材资产。

**本包以「文案卖点 × 图片素材 × 用户偏好」交叉分析为主线**（方法见 `references/copy-analysis.md`）：给文案打标（主卖点/行动钩子/语气句式）、给图片打标（画风/元素/福利），两套标签各自独立判定，再按「同类用户内部比较 / 相对该人群基线」口径交叉归因，产出每类人群一列的三联图报告。传统的整体/节点/分层/复用衰减/大盘 Benchmark 能力仍完整保留，作为配套。

**本 skill 是脱敏通用版**：不含任何具体游戏、平台、真实业务数据。所有游戏专属项集中在 `config/config.json`（见 `config/config.schema.md`），换一款游戏、换一个投放平台，只改配置，脚本与方法论文档都不用动。

> 由两套同源工作流合并而成：一套偏「自有投放台账」（可做用户分层），一套偏「平台大盘表」（只能做大盘对比）。两者差异已抽象成 `source.mode` 与 `report.narrative` 两个开关。

## 何时使用

- **（主线）按用户分层分析文案卖点偏好 / 图片素材偏好**：哪类卖点、哪类图对哪类用户更有效
- 给文案制定标签体系、逐条判读文案卖点/钩子/语气
- 对某款游戏在某投放平台的素材做复盘、打标、效果归因
- 建立/扩展视觉标签库、维护素材索引表、批量重命名素材图
- 分析不同用户分层、运营节点、画风、福利形式的效率差异
- 与大盘/对标游戏做 Benchmark，判断自身水位
- 测算素材缺口、输出排期与延展优先级
- 生成 HTML 复盘报告或在线智能文档

## 硬性规则（先读，违反会返工）

1. **配置是唯一事实源**：游戏名、平台、子表名、字段名、标签体系、节点档期、对标游戏、图片域名、叙事策略全部读 `config`。**禁止把具体值写进脚本或文档**。换游戏只改 config。
2. **原表一律只读**：数据源子表禁止写入。打标结果写进**新建子表** `source.tag_sheet`。
3. **打标必须逐张看图**：画风/画面元素/福利呈现只能用多模态看图判读，**禁止仅凭广告标题/描述推断**；文字只作辅助线索。
4. **图片缺失标「待人工」**并给低置信度，绝不用文字臆断填充。
5. **样本量 < `thresholds.min_sample` 的组只给方向性结论**，标注「样本不足」。
6. **每张交付物必须声明口径**：「唯一创意图（去重后）」与「投放记录行数」是两个数，禁止混用。例：M 条记录 = N 张唯一图。
7. **CTR 一律曝光加权**：`SUM(点击) / SUM(曝光)`，禁止对各行 CTR 取简单平均；每个结论带 样本/曝光/CTR 三个数。
8. **大盘对比必须双口径**：游戏级（曝光加权）与素材级（单张中位）都要算，两者结论可能相反，后者常是真瓶颈。
9. **游戏名变体先合并**：`benchmark.aliases` 收齐同一游戏的所有名字，不合并会算出 CTR≈0 的假结果。
10. **对外产物只用 CDN 网址**：`output.link_policy = cdn_only`，禁止出现本地路径/内网链接。本地图片目录只用于离线看图。此条只约束「报告正文里给人点的超链接（如查看原图）」，与第 13 条不冲突。
11. **文档迭代不留旧版内容**：口径升级后必须替换旧章节，禁止「新增一节 + 保留旧节」。见 `references/doc-sync.md`。
12. **叙事策略由配置决定**：`report.narrative` 控制是否展示排名/分位/头部游戏名。即便不进报告也要算出来留档，并在交付时口头告知业务方本人（不隐瞒，但不写进给更上层看的报告）。
13. **⭐ 用户偏好结论只做同类内部比较**：不同人群绝对 CTR 差来自人群精准度，不是素材好坏。所有偏好结论只能是「同类人群内部比较」或「相对该人群基线的 pp」，禁止跨人群硬比绝对 CTR。见 `references/copy-analysis.md`。
14. **⭐ HTML 报告必须离线自包含**：页面要正常显示所需的一切（画图库/样式/字体/图片）都要内嵌或随包自带，**禁止任何渲染依赖外链（script/link/img 的 src/href 指向 CDN）**——保证双击打开、转发给别人、断网都能出图。交付前用 `scripts/verify_html_charts.js` 跑**运行级渲染验证**（真实执行画图代码、确认每张图画出 SVG），不能只查占位符/语法。正文「查看原图」那种给人点的超链接不受此限（见第 10 条）。

## 工作流（七阶段）

### 阶段 1 · 摸底与取数
1. 读 `config`：确认 `source.mode`（own_ledger / market_table）、字段名映射 `fields`。
2. 先 `GROUP BY` 摸清记录分布与月份覆盖，**不要直接拉全量明细**。
3. 运行 `scripts/fetch_materials.py` → `master.csv` + 按图片链接去重下载唯一创意图。
   - 经验：投放记录数通常明显多于唯一图数——**按图打标、按记录回填**。
4. 抽样看 8–10 张不同时期的图，校准标签体系（首次执行或体系变更时必做）。

### 阶段 2 · 建立或复用标签库（视觉 + 文案两套）
- **视觉标签**（判图片画面）：`taxonomy.style/elements/benefit`，复用 `config/presets/` 预设或直接改 `config.taxonomy`。
- **文案标签**（判文案文本，主线）：`taxonomy.copy_main/copy_hook/copy_tone/copy_confidence`；主卖点单选判主句，钩子/语气多选判全句。逐条人工判读成 `copy_labels.json`（主句→标签）再回填。
- 两套**各自独立判定**：绝不用文案词推断画风，也不用画面推断卖点。
- 新建/扩展遵循四条：**互斥穷尽**（单选互斥、元素可多选叠加）、**可判定**（视觉只看画面、文案只读文本）、**可执行**、**粒度适中**（拆太细会样本不足）。
- 详见 `references/tag-taxonomy.md`（视觉）与 `references/copy-analysis.md`（文案）。

### 阶段 3 · 逐张看图打标
1. 唯一图按数量分 4–5 批，**并行派发子智能体**逐张用多模态 Read 打开图片判读，输出 JSON（style / elements / benefit / desc / conf）。提示词强调：真实观看、不得猜测、把握不足标「中」。
2. 主会话抽查 4–6 张校验质量。注意会话级图片缓存会让重复读图返回 unchanged——需复制文件并在 JPEG 头插 COM 段绕过（见 `references/table-ops.md`）。
3. 运行 `scripts/label_merge.py` 合并各批标签，按「图→记录」映射生成 `tagged.csv`（含节点标签）。
   - 坑：同链接多条记录时，映射必须保留**首次出现**的 rowid，否则回填大面积为空。

### 阶段 4 · 写入智能表格
运行 `scripts/write_smarttable.py`：新建打标子表（字段/选项从 config 生成）→ 分批写 → 设列宽 → 回读校验。接口限制见 `references/table-ops.md`。

### 阶段 5 · 效果分析
**常规口径**（`scripts/analyze.py` / `references/analysis-playbook.md`）：
- 维度：整体月度 / 节点 / 用户分层 / 画风 / 画面元素（多选包含口径）/ 福利呈现 / 画风×福利交叉 / **复用衰减**
- 复用衰减 `scripts/reuse_map.py`：按图片链接去重成唯一图，看「第 N 次复用」的 CTR 中位与曝光结构是否倒挂
- Benchmark `scripts/benchmark.py`：游戏级 + 素材级双口径，别名合并，算中位/排名/分位

**⭐ 主线：文案卖点 × 图片素材 × 用户偏好 交叉分析**（启用 `config.copy` 时）：
1. `scripts/analyze_copy.py`：一次性完成 **人群归一**（几十种写法→少数核心人群）、**素材块继承**（一条素材拆多行、文案/图只在首行）、**文案桥挂接**（用整段文案匹配旧台账复用视觉标签，免重复看图）、**文案标签回填**、**各维度×各人群加权 CTR** → `copy_base.csv` + `copy_results.json`。三份输入表用「内部列名」数据契约（见 `copy-analysis.md` 第四节），路径走命令行参数，不写死在 config。
2. `scripts/build_report_copy.py`：读 `copy_results.json` + config → 三联图 HTML（每类人群一列、TOP-N 标签、红虚线=该人群基线、n 标注），**画图库内嵌、零外链**。
3. `scripts/verify_html_charts.js`（Node，可选）：**运行级渲染验证**，真实执行画图代码确认每张图画出 SVG。
4. ⚠️ 铁律：只在**同类人群内部比较**或**相对该人群基线**下结论；n<min_sample 标注样本不足；挂接率写进口径声明；某卖点特别强时做**组内混杂检查**。方法见 `references/copy-analysis.md`。

### 阶段 6 · 产出交付物
1. **HTML 报告**：复制 `assets/report_template.html`，填 KPI、核心结论卡、分维度表、Benchmark、缺口测算、⚡行动建议。叙事按 `report.narrative` 裁剪。
   - **主线进阶报告**：用 `scripts/build_report_copy.py` 生成 `copy_report.html`（三联图），**画图库必须内嵌、零外链**，交付前跑 `verify_html_charts.js`。
2. **在线智能文档**（可选）：承载标签体系定义、结论、索引说明。⚠️ 若宿主安全层拦截 `file_path` 上传，改用 `blocks update` + 内联 mdx（见 `references/table-ops.md`）。
3. **文档对齐**（口径升级时）：按 `references/doc-sync.md`「拉块→删旧→改标题→插新→校验」五步。
4. 用文件展示能力交付。

### 阶段 7 · 缺口测算与排期
- 需求侧：投放天数 × 每日差异化张数；供给侧：历史验证高 CTR、可延展的底稿数
- 净缺口 = 需求 − 可复用；**明确写出三条假设**（每日张数、复用率、版本换新缓冲）
- 输出 P0–P3 优先级 +「暂缓」清单 + 按周排期

## 交付前自检清单

- [ ] 口径声明写了（唯一图 vs 投放记录、数据区间、来源）
- [ ] CTR 全部曝光加权，每个结论带 样本/曝光/CTR
- [ ] 样本不足的组已标注
- [ ] 大盘对比同时给了游戏级与素材级两个口径
- [ ] 游戏名变体已合并（aliases）
- [ ] 含复用衰减维度
- [ ] 产物中无本地路径，链接全是 CDN 网址
- [ ] 叙事裁剪符合 `report.narrative`；不进报告的扎心数据已口头告知
- [ ] **用户偏好结论只在同类人群内部比较 / 相对该人群基线，无跨人群硬比绝对 CTR**
- [ ] **进阶报告：挂接率写进口径声明；文案维度与图片维度未混用；样本不足组已标注**
- [ ] **HTML 离线自包含**：零渲染依赖外链（script/link/img 的 src/href），画图库已内嵌
- [ ] **运行级渲染验证**：`verify_html_charts.js` 真实跑过、每张图画出 SVG（不能只查占位符）
- [ ] 文档中无旧口径残留
- [ ] 锚点资产（索引表、内置数据表）未被误改
- [ ] 全文无具体游戏名/真实业务数字（本包为脱敏通用版）
