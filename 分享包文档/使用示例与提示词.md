# 使用示例与提示词

> 怎么把这套流程「叫起来」。分三种场景：给 Agent 的提示词、命令行、以及完整一轮复盘的对话节奏。
> ⭐ 本包主线是「文案卖点 × 图片素材 × 用户偏好」交叉分析，下面第一则提示词最常用。

---

## 一、给 Agent 的提示词（装了 Skill 之后）

### ⭐ 文案卖点 × 图片素材用户偏好分析（本包主线，最常用）
```
用 ad-material-review 做一次「文案卖点 × 图片素材 × 用户偏好」交叉分析：
- 目标：XX 游戏在 XX 平台 2026-Q1 的投放素材
- 数据源：在线表格「<投放规划表> → 明细子表」（原表只读）
- 人群：把「定向用户类型」几十种写法按 config.copy.segment_map 归一到 3 类核心人群
- 素材：一条素材拆多行、文案/图只在首行的，空白行按「继承上一行素材」处理
- 打标：文案按主卖点/行动钩子/语气句式逐条判读；图片若无标签，用「文案桥」匹配旧台账复用旧图标签
- 口径：CTR 曝光加权；偏好结论只做同类人群内部比较 / 相对该人群基线，别跨人群比绝对 CTR；样本不足标注
- 产出：三联图 HTML 结论报告（离线自包含，双击/转发/断网都能出图）+ 通吃素材清单 + 行动建议
```
> 方法详见 `skills/ad-material-review/references/copy-analysis.md`；脚本 `analyze_copy.py` → `build_report_copy.py` → `verify_html_charts.js`。

### 素材复盘（常规）
```
用 ad-material-review 做一次投放素材复盘：
- 目标：XX 游戏在 XX 平台 2026-Q1 的投放素材
- 数据源：在线表格「<投放明细表> → 明细子表」（原表只读）
- 重点看：画风、福利呈现、用户分层、复用衰减，以及跟大盘的双口径对比
- 产出：HTML 复盘报告 + 下月素材缺口与优先级
- 报告叙事：neutral（内部复盘用）
```
> 换叙事：把最后一行改成 `positive_only` 即切换为「只写优势与进步、排名不进报告」。

### 用户分层 / 受众分析
```
用 ad-material-review 的 user-analysis 方法，分析各人群分层对哪类素材更有效：
分层 × 画风 / 分层 × 福利 / 分层 × 文案卖点 交叉，结论必须带曝光量，标注样本不足的组，
只做同类人群内部比较，最后给出「哪个人群配哪类素材」的配比建议。
```

### 大盘 Benchmark
```
用 ad-material-review 跑大盘双口径对比：先 GROUP BY 游戏名看全部变体并合并，
再算游戏级（曝光加权）与素材级（单张中位）两个口径，给中位/排名/分位，
结论里说明两个口径是否矛盾。
```

### 资源 / 素材需求表
```
用 channel-resource-table 做 XX 平台 XX 专区的资源需求表：
先按规则文档判定申请资格与范围，产出「全景表」（内部）+「精简需求表」（对外）成对交付，
DDL 按 T 前倒推 / T 后顺推排，派生素材挂在 T 之后。
```

### 复盘 / 整理一批资料
```
用 retrospective 把这批资料做一次整理：先和之前的结论对齐，标出冲突，
再总结「下次走哪条路最省事」，剔掉凑数内容；整合资料走「先建地图、按需取用、每步留痕」。
```

## 二、命令行示例（不装 Skill 也能用）

**从包根目录执行**（能看到 `README.md` 和 `examples/` 的那一层）。

### 1. 空跑验证（常规三条，假数据，离线）
```bash
python skills/ad-material-review/scripts/analyze.py \
  --config examples/config.demo.json \
  --csv examples/tagged.sample.csv \
  --out examples/out/analysis.json

python skills/ad-material-review/scripts/benchmark.py \
  --config examples/config.demo.json \
  --data-dir examples \
  --out examples/out/benchmark.json

python skills/ad-material-review/scripts/reuse_map.py \
  --config examples/config.demo.json \
  --master examples/master.sample.csv \
  --tagged examples/tagged.sample.csv \
  --out examples/out/reuse_map.csv
```

### 1b. ⭐ 主线空跑（文案卖点 × 图片素材用户偏好分析，三步，全离线）
```bash
python skills/ad-material-review/scripts/analyze_copy.py \
  --config examples/config.demo.json \
  --planning examples/copy_planning.sample.csv \
  --labels examples/copy_labels.sample.json \
  --master examples/copy_master.sample.csv \
  --tagged examples/copy_tagged.sample.csv \
  --index examples/copy_index.sample.csv \
  --out-base examples/out/copy_base.csv \
  --out-json examples/out/copy_results.json

python skills/ad-material-review/scripts/build_report_copy.py \
  --config examples/config.demo.json \
  --results examples/out/copy_results.json --out examples/out/copy_report.html

node skills/ad-material-review/scripts/verify_html_charts.js examples/out/copy_report.html 4
```
> 第 3 步可选（需装 Node），用来确认 4 张图真的渲染出来了；不装也能跑完前两步。

### 2. 阶段 1 取数（需在线表格授权）
```bash
python skills/ad-material-review/scripts/fetch_materials.py \
  --config skills/ad-material-review/config/config.json \
  --out-dir ./data
# 只看 master.csv 不下图：加 --no-download
# 离线快照：加 --raw-json ./snapshot.json
```

### 3. 阶段 3 合并打标
```bash
python skills/ad-material-review/scripts/label_merge.py \
  --config skills/ad-material-review/config/config.json \
  --labels-dir ./data --pattern 'labels_b*.json' \
  --master ./data/master.csv --out ./data/tagged.csv
```

### 4. 阶段 5 分析（真实数据）
```bash
python skills/ad-material-review/scripts/analyze.py \
  --config skills/ad-material-review/config/config.json \
  --csv ./data/tagged.csv --out ./data/analysis.json
```

### 5. 素材图重命名（先预览再执行）
```bash
python skills/ad-material-review/scripts/rename_images.py \
  --map ./data/tagged.csv --dir ./data/素材图            # dry-run 预览
python skills/ad-material-review/scripts/rename_images.py \
  --map ./data/tagged.csv --dir ./data/素材图 --apply     # 确认后执行
```

### 6. 阶段 4 写打标子表（需授权）
```bash
python skills/ad-material-review/scripts/write_smarttable.py \
  --config skills/ad-material-review/config/config.json \
  --csv ./data/tagged.csv --batch 50
```

### 7. 生成资源需求表（需授权）
```bash
python skills/channel-resource-table/scripts/build_sheet.py \
  --spec skills/channel-resource-table/config/spec.example.json
# 先看 spec 长什么样：加 --dump-example
```

## 三、完整一轮复盘的对话节奏（推荐）

### 常规素材复盘
```
你  → 「用 ad-material-review 起一轮复盘，先摸底」
Agent → 读 config、GROUP BY 看数据分布与月份覆盖（不拉全量）
你  → 确认数据源与区间
Agent → 取数、去重下图、抽样 8-10 张校准标签体系
你  → 确认/微调标签体系（这一步最需要你）
Agent → 分批逐张看图打标 → 合并 → 写入新建子表
Agent → 出各维度 CTR、大盘双口径、复用衰减
你  → 「报告用 positive_only，扎心数据单独告诉我」
Agent → 生成 HTML 报告 + 缺口测算 + 优先级
Agent → 交付，并口头告知不进报告的数据
```

### ⭐ 主线（文案卖点 × 图片素材用户偏好分析）
```
你  → 「按三类核心人群做一次文案卖点 × 图片偏好分析，旧图标签能复用就复用」
Agent → 先 GROUP BY 定向用户类型，列全部写法给你确认归一映射（segment_map）
你  → 确认人群归属与核心人群
Agent → 文案逐条打标（主卖点/钩子/语气）；空白行继承上一行素材
Agent → 用「文案桥」匹配旧台账挂接图片标签，报告挂接率与未挂接原因
Agent → 各人群内部按卖点/钩子/画风/福利算曝光加权 CTR + 相对基线
你  → 「样本不足的标出来；别跨人群比绝对 CTR」
Agent → 生成三联图 HTML 报告（离线自包含）+ 运行级验证 4 图
Agent → 交付：每类人群的偏好 TOP、通吃素材、行动建议 + 口径声明
```

## 四、提示词里最好带上的四样东西

1. **目标与区间**：哪款游戏、哪个平台、哪段时间
2. **数据源**：哪张表、哪个子表，并声明「原表只读」
3. **重点维度**：想看什么（画风/福利/分层/复用/大盘；⭐ 主线则是卖点/钩子/语气 × 图片 × 人群）
4. **叙事与交付**：报告给谁看（`neutral`/`positive_only`）、要什么产物

做**主线**时再多带两样，Agent 基本不用追问：

5. **人群归一规则**：几十种写法归到哪几类核心人群（`copy.segment_map`），以及空白行怎么继承
6. **口径红线**：曝光加权、只做同类内部比较/相对基线、样本不足标注、挂接率如实声明、HTML 离线自包含

## 五、触发词在哪改

各 `SKILL.md` 顶部 `description` 里写了触发词。若你们团队的说法不同
（比如管「素材复盘」叫「素材周报」），改 `description` 里的关键词即可，否则 Agent 可能不自动加载。
主线触发词已包含「文案卖点 / 用户偏好 / 人群归一 / 文案打标 / 交叉分析」等，按需补你们的叫法。
