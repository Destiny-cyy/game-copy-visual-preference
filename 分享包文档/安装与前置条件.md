# 安装与前置条件

> 装之前先看这份。分两种用法：**只想看懂/空跑**（不需要装）和**装成 Skill 给 Agent 用**。
>
> 本包主线是「**文案卖点 × 图片素材 × 用户偏好**」交叉分析；下面第四节给了它的三步空跑验证。
> 主线空跑只用 Python（外加可选的 Node 用来验证报告里的图真的画得出来），不需要联网、不需要任何在线授权。

---

## 先分清两种用法

| 用法 | 需要装吗 | 需要联网/授权吗 |
|---|---|---|
| 读文档、看方法 | 不需要 | 不需要 |
| 用假数据把分析脚本空跑一遍 | 不需要 | 不需要 |
| 接真实数据源做完整复盘 | 建议装成 Skill | 需要在线表格能力 |
| 让 Agent 自动触发这套流程 | 需要装 | 需要 |

---

## 一、把三个 Skill 装进 Agent（可选）

把 `skills/` 下的三个目录**整目录**拷到你的 Agent 的 skills 目录：

```bash
# 示例：通用 Agent 用户级 skills 目录
cp -r skills/ad-material-review      {{SKILL_ROOT}}/
cp -r skills/channel-resource-table  {{SKILL_ROOT}}/
cp -r skills/retrospective           {{SKILL_ROOT}}/

# 也可以按你的 Agent 约定调整根目录
# cp -r skills/* {{SKILL_ROOT}}/
```

三个目录互不依赖，也可以只装其中一个。装好后重启/刷新会话，用触发词即可自动加载
（触发词写在各 `SKILL.md` 顶部的 `description` 里，可按你们团队习惯改）。

## 二、前置条件清单（逐项确认）

### 1. Python 3.8+（必需）
脚本只用**标准库**（csv / json / argparse / subprocess / statistics / urllib），**无需 pip 安装任何依赖**。

```bash
python --version
```

### 2. 配置文件（用 ad-material-review 时必需）
```bash
cd skills/ad-material-review
cp config/config.example.json config/config.json
```
按 `config/config.schema.md` 或包根《迁移到新游戏指南.md》填真实值。
**不填也能空跑**（会回退到示例配置并打印提示）。

> ⚠️ 一个容易踩的点：如果显式传了 `--config 路径` 但文件不存在，脚本会**直接报错退出**，
> 不会悄悄用示例配置——这是故意设计的，避免「以为配置生效其实没有」。

> ⭐ 做主线分析还要填 `config.copy`：把源表几十种人群写法按 `segment_map` 归一到几类核心人群，
> 定好 `core_segments`、`chart_dims`、文案标签（`copy_main`/`copy_hook`/`copy_tone`）。
> 这些全是配置项，脚本一行都不用改。说明见 `config/config.schema.md` 的 `copy` 区块。

### 3. 在线表格 / 智能文档能力（只在接真实数据时需要）
- 本包脚本用 `table-cli`（在线表格连接器）作示例前缀，需要连接器已连接、已授权。
- 若你们用别的兼容 CLI/平台，设置环境变量 `TABLE_TOOL_CLI` 即可切换命令，其余逻辑通用。
- 验证能力是否可用：
```bash
table-cli doc create --json '{"doc_type":"sheet","doc_name":"测试表"}'
# 返回 errcode 0 且有 url = 可用
```

### 4. 多模态看图能力（打标阶段需要）
阶段 3 需要 Agent 能「逐张打开图片看」。若你的 Agent 不具备，可人工打标后
把结果写成 `labels_b*.json`（格式见 `examples/labels.sample.json`），其余流程照跑。

> ⭐ 主线里若选择「**复用旧台账的图片标签**」，就不必逐张重看图：用「文案桥」把新表文案匹配回旧台账，
> 挂上旧图的画风/元素/福利标签即可（脚本 `analyze_copy.py`，三份旧台账文件由命令行传入）。
> 挂接率会写进结果里；没挂上的记录只不进图片维度，文案维度照常统计。

### 5. 平台规则文档（用 channel-resource-table 时需要）
申请资源位前，需准备你们平台**官方**的规则文档（位置清单、规格、门槛、对接入口）。
本包不含任何真实平台规则，示例全是占位。

### 6.（可选）子 Agent 并行能力
阶段 3 建议把唯一图分 4–5 批并行打标。不支持并行也能串行做，只是慢一点。

### 7.（可选）Node.js —— 只用来验证「报告里的图真的画得出来」
`verify_html_charts.js` 会真实执行 HTML 里的画图代码，确认每张图都渲染出来了。
**不装 Node 不影响主流程**（分析、生成报告都照跑），只是少了这道「白屏保险」。
装了的话，双击打开报告前先跑一次它最稳：

```bash
node --version
```

## 三、权限与安全边界（重要）

- **原表一律只读**：数据源子表禁止写入；打标结果写进**新建**子表 `source.tag_sheet`。
- **对外产物只放 CDN 网址**：`output.link_policy = cdn_only`，禁止本地路径/内网链接出现在可分享产物里。
- **不要把真实业务数据写回脚本或提交到公开仓库**：真实值只放 `config.json`，且仓库默认私有。
- **删除文件走回收站**：本包工作流里涉及清理时，一律先确认、不直接删。
- **⭐ HTML 报告必须离线自包含**：页面要正常显示所需的一切（画图库 / 样式 / 字体 / 图片）都要**内嵌或随包自带**，
  `<script>/<link>/<img>` 的 `src`/`href` 不得指向外网 CDN——保证**双击打开、转发给别人、断网都能出图**。
  画图库 `echarts.min.js` 已随包自带并内嵌进 HTML，不用你额外准备。
  > 注意：这条管的是「页面要显示就必须加载的**渲染依赖**」。报告正文里给人**点开看原图**的 CDN 网址超链接是内容链接，不受这条限制。

## 四、装完怎么验证

```bash
# 从包根目录执行（假数据空跑，不需要任何授权）

# ① 常规素材复盘
python skills/ad-material-review/scripts/analyze.py \
  --config examples/config.demo.json \
  --csv examples/tagged.sample.csv \
  --out examples/out/analysis.json

# ② ⭐ 主线：文案卖点 × 图片素材用户偏好分析（三步，全离线）
python skills/ad-material-review/scripts/analyze_copy.py \
  --config examples/config.demo.json \
  --planning examples/copy_planning.sample.csv \
  --labels examples/copy_labels.sample.json \
  --master examples/copy_master.sample.csv \
  --tagged examples/copy_tagged.sample.csv \
  --index examples/copy_index.sample.csv \
  --out-base examples/out/copy_base.csv \
  --out-json examples/out/copy_results.json
python skills/ad-material-review/scripts/build_report_copy.py \
  --config examples/config.demo.json \
  --results examples/out/copy_results.json --out examples/out/copy_report.html
node skills/ad-material-review/scripts/verify_html_charts.js examples/out/copy_report.html 4
```

能打印出各维度 CTR 表 = 环境 OK；主线三步能生成 `copy_report.html`、验证脚本报「4 图全渲染」= 主线 OK。
`node` 那步是**可选的运行级验证**（验证报告里的图真的画得出来，而不是只检查了文件里有没有字），不装也能跑完前两步。
完整命令见 `examples/README.md`；更细的字段说明见 `config/config.schema.md`。
