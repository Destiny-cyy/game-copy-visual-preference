# 团队定制清单

> 换团队 / 换项目用之前，按这份清单过一遍。分成「必改 / 可选改 / 不用改」三档。

---

## 必改（6 处）

### 1. 配置文件 `config/config.json` ⭐ 最容易忘
`ad-material-review` 的**全部游戏专属信息**都在这里。换游戏必须整份重填：
游戏名、平台、docid、子表名、字段名、标签体系、档期、对标游戏、图片域名、叙事策略。
→ 逐字段说明见 `skills/ad-material-review/config/config.schema.md`，一步一步见包根《迁移到新游戏指南.md》。

> 不填的话脚本会回退到示例配置空跑演示（并打印提示），**不会**用真实数据。

### 2. 标签体系 `taxonomy` / `presets/`（含文案标签）
`config/presets/` 里的两套预设是**示例**（偏暗黑幻想 / 偏科幻射击），不是任何真实项目口径。
换成你们品类的画风/元素/福利分类；`segments` 必须与源表「广告类型」实际取值一致。
⭐ **文案标签也是两套独立体系**：`copy_main`（主卖点，单选）/ `copy_hook`（行动钩子，多选）/ `copy_tone`（语气句式，多选）
要按你们项目的文案说法重写（例如偏「版本/福利/职业/构筑」，或偏「上线/通行证/赛事/折扣」）。
方法见 `references/copy-analysis.md`，两个 preset 各给了一套文案标签当样板。

### 3. ⭐ `config.copy`：主线的「人群归一 + 图表」配置（本版新增）
主线分析全靠这一块，换项目必改：

| 字段 | 换成什么 | 不改会怎样 |
|---|---|---|
| `copy.segment_map` | 把源表「定向用户类型」几十种写法，按**有序优先级**归一到几类核心人群 | 人群映射不到 → 大量记录落进 other，偏好分析为空 |
| `copy.core_segments` | 你们真正要对比的几类核心人群（报告按它一列一列排） | 报告列数、结论对象不对 |
| `copy.chart_dims` / `chart_topn` | 报告要出哪几个维度、每组取前几名 | 图跟业务关注点对不上 |
| `copy.segment_display` / `segment_colors` / `short_labels` | 人群在报告里的显示名、配色、短标签 | 图上名字太长/撞色 |
| `copy.bridge.enabled` | 是否用「文案桥」复用旧台账的图片标签 | 新表没有图标签时，图片维度会空 |

> 三份旧台账文件（master / tagged / index）由命令行 `--master/--tagged/--index` 传入，**不写死在 config**。

### 4. 触发词（决定 Agent 会不会自动匹配）
各 `SKILL.md` 顶部 `description` 里的触发词，换成你们团队的说法，否则说「素材周报」它可能不加载。
主线触发词已含「文案卖点 / 用户偏好 / 人群归一 / 文案打标」等，可按你们的叫法补。

### 5. 平台规则（用 channel-resource-table 时）
`references/` 里的规则章节号、门槛、天数**全是占位**。
必须读你们平台的**官方规则文档**重新填 `config/spec.example.json` 与表内容。别沿用示例规则。

### 6. 图片域名 / 链接口径
`output.cdn_base` 与 `referer` 换成真实值；对外产物一律只放 CDN 网址（`link_policy: cdn_only`）。
注意区分：**报告正文里给人点开看原图的 CDN 网址**是内容链接，允许；**页面渲染必须加载的库/样式**必须内嵌，不许外链。

## 转发给外部前，额外补这 2 项（分发方专用）

上面 6 处是「自己用」要改的；如果你是**要把这个包发给别的团队 / 外部合作方**，还要补两处，否则接收方不知道找谁、也不敢用：

| # | 要补什么 | 补在哪 | 不补会怎样 |
|---|---|---|---|
| 1 | **维护人 / 反馈渠道**：谁维护、有问题找谁、改动按什么规矩审 | 直接写进本文件，或随包附一页说明 | 接收方改错了没人兜底，问题无处反馈 |
| 2 | **保留许可与署名**：再分发时一并保留项目 MIT 许可和第三方组件许可/声明 | `LICENSE`、`THIRD_PARTY_NOTICES.md`、`LICENSES/` | 删除声明可能违反上游许可，或使授权范围不清 |

不要用团队自有许可证覆盖本包或第三方组件的原许可；如需加入自有内容，另行标注其权属和授权范围。

补完再过一遍总 `README.md` 第十一节的「**分发前 5 项自检**」（重扫敏感词 → 确认无真实 `config.json` → 解压后空跑 → HTML 零外链 → 运行级验证图能画出来）。

## 可选改（按需）

| 位置 | 内容 | 说明 |
|---|---|---|
| `config.thresholds` | `min_sample` 等门槛 | 样本量小的项目可调低，但结论要标「样本不足」 |
| `config.report.narrative` | 叙事策略 | 与业务方确认报告能写什么（见下） |
| `config.nodes` | 档期名与日期 | 换成你们项目的档期，**每次复盘前向业务确认** |
| `config.benchmark.peers` | 对标游戏 | 换成同题材、量级接近的参照 |
| `config.copy.chart_dims` / `chart_topn` | 主线报告出哪几张图、每组前几名 | 按业务关注点增删维度 |
| `assets/report_template.html` | 配色 / 结构 | 按团队视觉规范改；占位符 `{{...}}` 保留 |
| `assets/report_template_copy.html` | ⭐ 主线三联图报告的配色 / 结构 | 同上；`__XXX__` 占位符保留，画图库内嵌位别动 |
| `TABLE_TOOL_CLI` | `table-cli` | 若使用别的兼容 CLI/平台，设置该环境变量，其余逻辑通用 |
| `channel-resource-table/scripts/table_sheet.py` 的 `BLUE` | 主题配色 | 按团队规范改色值 |

## 不用改（通用能力，动了反而容易错）

- **七阶段工作流本身**（摸底 → 打标 → 分析 → 报告 → 缺口测算）
- **曝光加权 CTR 口径**、样本不足标注、双口径 Benchmark、复用衰减逻辑
- **⭐ 主线三条口径铁律**：人群归一有序优先级、素材块继承（未标注行不继承）、文案桥挂接率如实声明
- **⭐ 偏好结论只做「同类人群内部比较 / 相对该人群基线」**，绝不跨人群硬比绝对 CTR（老用户 CTR 天然高，是人群精准度差异，不是素材偏好）
- **⭐ HTML 报告离线自包含**：画图库内嵌、零渲染依赖外链、交付前跑 `verify_html_charts.js`
- **「原表只读」**「对外只放 CDN 网址」「单元格只填结论」等硬规矩
- **「先对齐 / 每步留痕 / 删前先问」** 三条复盘底线
- **「不通读，先建地图、按需取用」** 的资料整合方法
- 脚本的容错列名、分批写入、回读校验、dry-run 重命名等工程细节

## 换团队时最容易漏的三件事

1. **人员 / 角色称谓**：「品牌方 / 渠道 / 平台」到底指谁，先问清楚再动手（见 `content-principles.md` 第一节）。
2. **叙事尺度**：报告给谁看、能不能写排名和垫底，务必先跟业务方确认（`report.narrative`）。
3. **档期日期**：`nodes` 的日期多为推断值，每次复盘前确认，别沿用上一轮的。
4. **⭐ 人群写法没收齐**：`copy.segment_map` 漏了几种写法，那批记录就不进偏好分析。先 `GROUP BY 定向用户类型` 看全部取值。

## 第一次用的建议

**先拿一小批数据试跑**（比如一个月、几十张图），重点看四件事：

1. 字段名对不对（`config.fields` 与源表一致）
2. 标签体系能不能 unambiguous 地判（有没有大量「中」置信度）
3. 口径声明有没有写清（唯一图 vs 投放记录）
4. 报告叙事尺度合不合业务方预期

做主线时再多加两项：

5. **人群归一率**：`copy.segment_map` 覆盖了多少种写法，落到 `other` 的多不多
6. **文案桥挂接率**：多少记录成功挂上了旧图标签，未挂接的是不是新文案/改过字的文案

这六项没问题，再放量到全周期。
